# `arena` Benchmark Task

## Task identity and overview

Task name: `arena`

Benchmark family: structural representation / structural-navigation replay

| Symbol   | Surface | Description                                                             |
| -------- | ------- | ----------------------------------------------------------------------- |
| $obs[t]$ | yes     | observation identifier at time t                                        |
| $x'[t]$  | yes     | decoded observation identifier at time t (same as $obs[t]$ in v1)       |
| $a[t]$   | yes     | action at time t                                                        |
| $x[t]$   | —       | latent "what" sensory state at time t (LEC encoded sensory)             |
| $g[t]$   | —       | latent "where" location state at time t (MEC encoded topology)          |
| $p[t]$   | —       | latent sensory-location state at time t (HPC encoded conjunctive state) |
| $M$      | —       | memory state produced by structural learning (hippocampal memory store) |

_Surface_ symbols appear in the task input/output contract.
_Model-internal_ symbols (—) are emergent representations the model learns but are not part of the task-level data contract.

Canonical package path:

```text
src/ehc_sn/tasks/arena/
```

Arena is the structural-learning task family. The model traverses spatial layouts (grid worlds generated by `dungeongen` or `openfield`) via random-walk replay and learns to predict the observation at each step from its preceding internal location belief ($g[t-1]$) and action ($a[t-1]$). The surface task is observation prediction; the scientific purpose is acquiring structured environmental representations — grid-cell-like spatial encodings ($g[t]$), sensory codes ($x[t]$), conjunctive bindings ($p[t]$), and an episodic memory store ($M$) — that downstream reasoning tasks such as `goalchain` consume.

The core problem is:

```text
given the previous believed location (g[t-1])
and previous action (a[t-1]),
predict the observation (obs[t]).
```

By repeatedly visiting and revisiting locations, the model must learn to associate observations with locations and recall those associations on subsequent revisits — forming the structural knowledge that later tasks depend on.

## Relationship to other tasks

### Layout sources (upstream)

Arena consumes `SpatialLayout` objects from layout generators. The task is layout-agnostic by contract: any source that produces a valid `SpatialLayout` (see `spec/spec-openfield-layout.md`) can feed arena trajectory generation.

Current layout sources:

| Source       | Topology       | Spec                                   |
| ------------ | -------------- | -------------------------------------- |
| `dungeongen` | dungeon graphs | `scripts/data-gen/build-dungeongen.py` |
| `openfield`  | square grid    | `spec/spec-openfield-layout.md`        |

### Structural-learning prerequisite for `goalchain`

Arena is the foundational pre-training phase for the `goalchain` task (see `docs/docs/tasks/goalchain.md`). During data generation for `goalchain`, a pre-trained arena model is run over a layout to produce the episodic memory state ($M$) and latent representations ($g[t]$, $p[t]$). `goalchain` then tests whether the model can use that memory to solve goal-conditioned sequence-reasoning problems.

```text
arena (structural learning)
    → model trained to encode layouts and form observation-location bindings
    → produces emergent memory state ($M$) and latent representations
    → goalchain data-gen extracts these for downstream evaluation
```

Arena itself does not output $M$ as a task contract — $M$ is an emergent model internal that the `goalchain` data pipeline captures from a trained model's forward pass.

### Relationship to `seqmaze`

`seqmaze` isolates pure transition-graph reasoning without spatial grounding. Arena provides the spatial grounding that `seqmaze` deliberately removes. The two tasks bookend the structural-learning-to-reasoning spectrum.

## Scientific purpose

Arena tests whether a model can acquire structured environmental knowledge purely from sequential experience. No explicit spatial coordinates or topology are provided to the model during training (arena replay v1 is topology-free). Spatial structure must be inferred from action-conditioned observation transitions alone.

The relevant EHP computation is:

```text
learn the map
```

Interpretation:

| Component             | Role in `arena`                                             |
| --------------------- | ----------------------------------------------------------- |
| MEC-like structure    | learns transition structure and location encoding ($g[t]$). |
| LEC-like content      | learns observation identity encoding ($x[t]$).              |
| HPC / episodic memory | binds observations to locations ($p[t]$, $M$).              |

### Why `accuracy_revisit` is the primary metric

On the first visit to a location, the observation is novel — the model has no basis for prediction beyond the prior distribution. First-visit accuracy is therefore dominated by chance. On subsequent revisits, the model must recall what observation was previously at that location. `accuracy_revisit` isolates **episodic memory recall** from the confound of exploration. `accuracy_all` conflates both effects and dilutes the scientific signal.

## Input and output

### Adapter input (task-data → model)

Arena replay v1 is topology-free. The model receives only step-level identifiers and flags; no spatial coordinates, valid-action mask, or location id are exposed.

| Variable          | Description                              | Shape / dtype  |
| ----------------- | ---------------------------------------- | -------------- |
| `observation_id`  | current observation identifier           | `(B, 1)` int64 |
| `previous_action` | action that produced the current state   | `(B, 1)` int64 |
| `landmark_id`     | optional landmark / shiny-cue identifier | `(B, 1)` int64 |
| `step_count`      | transitions taken so far in the episode  | `(B, 1)` int32 |
| `episode_start`   | `True` on the first step of an episode   | `(B,)` bool    |

`landmark_id` may be `None` when the layout source does not provide landmarks.

### Adapter output (model → evaluation)

| Variable     | Description                  | Shape          |
| ------------ | ---------------------------- | -------------- |
| `obs_logits` | predicted observation logits | `(B, obs_dim)` |

Targets used for supervision and evaluation:

| Variable         | Description                                   |
| ---------------- | --------------------------------------------- |
| `observation_id` | ground-truth observation id for this step     |
| `is_revisit`     | `True` if this step revisits a prior location |

> **Teaching signal**: The `observation_id` in the adapter input is a teaching signal (error correction / learning target). The model's real predictive pathway is $g[t-1], a[t-1] \rightarrow obs[t]$ — the input observation provides feedback but is not the primary predictive input. This is why $g[t-1]$ (model-internal, absent from the surface contract) appears in the core problem statement.

## Corpus and data generation

### Frozen v1 channels

The arena replay corpus stores nine frozen channels per sample, precomputed
at build time from layout walks:

```text
trajectory_row              — (N, T_max) int32, -1 sentinel on padded steps
trajectory_col              — (N, T_max) int32, -1 sentinel on padded steps
trajectory_observation_id   — (N, T_max) int32
trajectory_previous_action  — (N, T_max) int32, step 0 = STAY, -1 on padded
trajectory_landmark_id      — (N, T_max) int32, -1 when absent or padded
trajectory_is_revisit       — (N, T_max) bool,  False on padded steps
trajectory_episode_start    — (N, T_max) bool,  True only at step 0
trajectory_valid_step       — (N, T_max) bool,  = (t < trajectory_length)
trajectory_length           — (N,)       int32
```

Spatial arrays (`topology`, `observations`, `mask_valid`) are also stored
per-episode so evaluation providers and trace builders never need external
parent resolution.

### Data generation

```bash
# Requires dungeongen shared substrate first:
python scripts/data-gen/build-dungeongen.py build-all
python scripts/data-gen/build-arena.py build-all

# Or with openfield layouts:
python scripts/data-gen/build-arena.py materialize-task \
    --layout-root data/interim/openfield/tem-square/v1
```

Output path: `data/processed/arena/<corpus>/v<version>/`

## Benchmark and evaluation

### Arena-Struct track

| Aspect             | Value                                       |
| ------------------ | ------------------------------------------- |
| Benchmark track    | Arena-Struct                                |
| Claim family       | `structural_representation`                 |
| Execution mode     | replay                                      |
| Primary metric     | `accuracy_revisit`                          |
| Secondary metrics  | `accuracy_all`, `correct_all`, `count_all`, |
|                    | `correct_revisit`, `count_revisit`          |
| Diagnostic metrics | `accuracy_ancestral_revisit`                |
|                    | `accuracy_retrieved_revisit`                |

### Score accumulation

The arena structural score uses additive accumulation: raw counts (`correct_*`, `count_*`) are summed across batches, then accuracy scalars are derived from the totals. This avoids the numerical error of averaging per-batch accuracies.

### Evaluation primitives

| Class                   | Role                                              |
| ----------------------- | ------------------------------------------------- |
| `ArenaScoreReport`      | canonical additive structural score for one batch |
| `ArenaEpisodeSemantics` | episode-semantic flags attached to one step       |
| `ArenaStepScore`        | per-slot observation prediction correctness       |
| `ArenaCaseMetrics`      | per-case scalar aggregates for Arena-Struct cases |

Primary metric source: `ehc_sn.tasks.arena.evaluation.ArenaScoreReport`.

## Open questions

1. **Revisit semantics across layout families**: In `dungeongen`, rooms create natural revisit structure. In `openfield` (uniform square grid), revisits depend on random-walk statistics. Does `accuracy_revisit` retain the same interpretation across layout families, or should the metric be family-conditioned?

2. **Transfer to `seqmaze`**: Arena provides spatial grounding; `seqmaze` removes it. Should there be a transfer experiment (arena → seqmaze) to test whether spatial structural knowledge improves pure transition-graph reasoning?

3. **Autoencoder for latent ↔ decoded translation**: `goalchain` needs to translate between latent locations ($g[t]$) and decoded topology locations ($g'[t]$). Should arena training include an auxiliary autoencoder loss for this mapping, or should a separate encoder-decoder be trained post-hoc on arena-produced latent states?
